# Automatic scrap cutoffs

Finish nesting, then choose **Nest > Automatic Scrap Cutoffs (All Plates)** to process the entire nest with one dialog. **Plate > Automatic Scrap Cutoffs** still processes only the active plate. The manual **Sheet Cut-Off** command remains available.

## Preview and apply

1. Finish or cancel any active nesting/fill operation first, and wait for it to finish stopping; closing its progress window alone does not finish the operation. Enter the maximum strip spacing along the sheet's length. The initial value is **35 in**, or **889 mm** for a metric nest. This is the maximum distance between new cut lines, not the length of a cut.
2. Set **Minimum strip**, initially half the spacing (**17.5 in** or **444.5 mm**). The first strip from the origin-side sheet edge and each strip between successive new lines stay between this minimum and the spacing; the last strip before the separator or sheet end can be shorter. This field follows spacing changes until you edit it. Setting it equal to spacing restores the fixed grid.
3. Set **Minimum tail to keep**, initially **12 in** or **304.8 mm**. This measures the reusable tail's length along X, after separator clearance, not its area. A shorter tail does not get a new final separator and is cut into strips with the rest of the skeleton; a tail at or above the minimum can be retained. Zero allows any positive tail.
4. Opening the modal dialog previews the initial proposal. After changing a setting, choose **Preview** to refresh it. Cuts run across the active sheet's actual width, advancing along X from the origin-side edge in the plate's quadrant. A bold green or red status line states what **Apply** will do; the occupied span, used span, separator X, retained tail, and strip cut length versus the fixed grid appear as measurements. The details list reports only issues and notices. The sheet cannot be edited while the dialog is open.
5. Choose **Apply** (or **Apply to All Plates**) to recalculate against the current parts/settings and add ordinary cutoff definitions at the end of each plate's cutting sequence. Blocked or empty proposals add nothing. Existing parts and manual cutoff definitions are not moved or reordered. **Cancel**, Escape, and closing the dialog discard the detached preview.

For the Nest command, the on-sheet overlay and upper measurements show the active plate; a per-plate table lists each plate's proposed cut-off count, occupied and used spans, retained tail, and readiness (Ready, Blocked, or No change), while the details list reports only issues and notices, each prefixed with its plate number. Each plate uses its own dimensions, quadrant and part spacing with the dialog's common spacing/minimum-strip/minimum-tail settings and current cutoff clearance/direction settings. No plate navigation or per-plate confirmation is required. Empty or unchanged plates are left untouched. A blocking conflict or invalid plate prevents changes to **all** plates, with the plate number reported; resolve it before retrying. If application fails after changes begin, all touched plates' original cutoff programs and sequence are restored. An explicit incomplete-recovery warning requires manual review before saving or cutting.

An empty sheet is left untouched. Invalid input or out-of-sheet part geometry prevents automatic planning. Excessively small spacing is rejected rather than allocating an unbounded number of cuts. Small bounded discrepancies between converted material and cached bounds—including amplified roundoff in fitted near-tangent arcs—are accepted without changing the part or its program. That allowance is absolute (10⁻¹⁰ model units), not a count of floating-point steps, so it does not shrink for parts near the origin: an arc whose end radius differs from its start radius by less than `Tolerance.Epsilon` is converted without refitting its centre, and rotated imported arcs can then rebuild a start point ~5 × 10⁻¹¹ outside the cached bounds. The same conservative numerical padding applies to cutoff pruning and exclusions. Their broad-phase envelope uses the farther edge of the cached box and converted perimeter; a cutoff within the narrow uncertainty band at a cached edge gets a full-envelope exclusion instead of relying on a near-tangent contour intersection. Elsewhere the contour is retained for precise trimming. Larger arc-center discrepancies still prevent automatic planning rather than risking a cut through material; repair the geometry before retrying.

## Preserving the unused tail

A proposed tail shorter than **Minimum tail to keep** is left attached to the scrap skeleton by omitting the final separator. The strip grid then continues to the sheet end exactly as it would with no room for a separator, so no strip exceeds the spacing, and no retained tail is claimed. For example, on a 144-inch sheet used through 139.75 inches, the 4-inch tail is too short to keep; the skeleton gets a fourth line near 140 inches instead of leaving a 39-inch final strip from 105 inches. Existing cutoff definitions—including an end cutoff from an earlier run—are never removed by this setting.

Only real parts contribute to the occupied envelope; existing cutoff parts do not. When there is room, the final separator is beyond the furthest occupied extent by the larger of plate part spacing and cutoff part clearance, plus numerical tolerance. Repeated skeleton cuts stop before that separator. The larger margin affects only the separator: repeated cuts keep the existing manual-cutoff clearance behavior.

Cutoff trimming measures clearance from the part contour, excluding tagged lead-in and lead-out moves when building the closed outline. Leads must not turn a recessed outline into a convex hull and leave oversized gaps elsewhere. Genuinely open contours (a tab gap, for example) still use the conservative hull/bounds fallback, but the hull is built from the material contour only: a cut-off may cross a lead, and hulling a lead's pierce point stopped cut-offs far short of the part. With a nonzero clearance, a line passing exactly through a corner of the clearance outline is trimmed to the outline like any other line. Automatic strip lines sit on a regular lattice and often land on such corners; they once fell back to the part's bounding box there, and the strip search preferred those lines because the box fallback measured as less cutting. The conservative curve/offset approximation can leave a small extra gap (about 0.0003 in on a straight edge at the default 0.02-in clearance), not an extra quarter inch.

If no safe separator fits inside the sheet, there is no retained-tail claim and the nominal cuts may cover the full sheet length. A proposed tail is not reported as separated unless its generated program spans the full sheet width. An active clamp blocks any proposed full-width line whose X coordinate falls in the clamp's whole footprint plus its clamp clearance, including a nominal grid line or an equivalent existing line. A tolerance-close existing line is tested at its own X as well as the proposed X, because that existing line is what would be certified. A same-line manual cut with different limits still blocks the whole plan, even on a clamp. Blocked lines are skipped with a clamp diagnostic; a blocked tail also reports `NoSafeTailSeparator` rather than claiming separation. Removed clamps on a sheet are absent from its active zones and do not block cuts. Stored zones are relative to the sheet's lower-left corner; the planner maps them into the plate's quadrant frame (the same frame as part and cut-off coordinates) before comparing, so the rule holds in all four quadrants. Obstructed or minimum-length-filtered lines produce diagnostics; they are not proof of a completed partition.

For a 120-by-81-inch sheet whose parts extend through 80 inches, the fixed grid would put skeleton lines at 35 and 70 inches, followed by a separator beyond 80 inches at the required margin. With a 17.5-inch minimum strip, the planner can move those two lines toward the origin to shorten their trimmed cut segments. The separator does not move, and there is no line at 105 inches through the retained tail.

## Keeping a band across the top

When the parts leave an unused band beyond them along Y (away from the origin), the band can be kept as a remnant instead of being sliced by the strip lines:

- An existing full-length horizontal cut-off that no part material reaches past, with a band at least **Minimum tail to keep** wide beyond it, is honored: every new vertical line runs from the origin-side edge up to that cut-off and stops there. With several, the one nearest the parts (the largest band) is used. This applies to every caller.
- The desktop dialog and Plan Cutting's `Add scrap cut-offs` also propose a new full-length horizontal separator beyond the parts, at the same margin as the X tail separator, when the band is at least **Minimum tail to keep** wide and its area beats the X tail it competes with. The vertical lines then stop at it. API callers opt in with `AutomaticCutOffOptions.KeepHorizontalRemnant`; without it they get full-width lines unless a horizontal cut-off already exists.
- Beside a kept band, the X tail becomes a corner piece. Its separator stops at the band too, and it is kept only when both its length and the distance to the band are at least the minimum; otherwise the strip lines continue to the sheet end.

For a 96-by-48-inch sheet with parts through Y 23 and a horizontal cut-off at Y 23.57, the 35-inch strip lines (shifted as usual) cut from Y 0 to 23.57 and the 24.43-inch band stays whole. Rerunning recognises the stopped lines as existing. A new separator is not proposed when it would cross an active clamp or a same-line manual cut with other limits, or when its program is not one uninterrupted cut; the details list reports `NoSafeHorizontalSeparator`, and the lines cross the full width. A `HorizontalRemnant` notice reports the separator's Y and the band width. The separator splits the sheet, so [Part sequencing](#part-sequencing) cuts it last.

## Shifting strip lines

The preview searches line positions together to minimize the total emitted strip-line cutting length after part clearance and minimum-segment filtering. Equal lengths favor fewer pierces, then less total movement from the fixed grid. The number of new lines in each span stays at the fixed-grid count; it never adds cuts to chase a shorter path. For example, a part edge at 34.75 inches can make a 35-inch line run beside much of the part, while a small shift toward the origin lets that line cross the part and skip its material. The preview reports the measured strip-cut length and the corresponding fixed-grid length, including when Minimum strip equals spacing; a `ShiftedCut` notice identifies moved lines. Because the lines are optimized together, an individual line can cut slightly more while the total falls; its notice reports that local increase rather than a negative saving.

Existing full-width vertical cut-offs inside the used span become fixed strip boundaries; the planner fills only gaps longer than the spacing, never moving or duplicating the manual cut. A partial manual cut is not a boundary and its position is avoided. Active clamps exclude candidate positions including their clamp clearance. If a gap cannot place all its lines outside clamps, it falls back to nominal lines and reports any blocked cuts under the existing guard. An unchanged rerun adds nothing. The desktop defaults to shifting; API callers that omit `MinimumStripLength` retain the fixed-grid behavior.

## Limits and operator review

Each trimmed segment of a cut-off is materialized as a part of its own with its own place in the cutting sequence (see [Part sequencing](#part-sequencing)), so one line can be cut in pieces, each where the route passes it. **View > Draw Rapids** follows the complete cutting sequence: an incoming rapid ends at a segment's pierce, and the next part's rapid starts at that segment's cutting endpoint—not its pierce. The cut simulation mutes each segment until the torch reaches it. This display does not add a return move or alter the cutoff program.

- Maximum strip spacing is not a disconnected-scrap guarantee. Clearance gaps and suppressed short segments can leave bridges between scrap regions. This command does **not** certify that every connected scrap piece is disconnected or fits a hopper.
- The active sheet's physical width is used, not a hard-coded 81 inches. Check the actual width against the hopper; a wider sheet is not automatically hopper-compatible.
- Internal-hole scrap is not processed. This command reuses the outside-skeleton behavior of manual cutoffs; it does not force cuts through parts or remove clearance to guarantee separation.
- Review the preview and posted NC using the normal machine-review process before production cutting.

## Outlined sheets

A plate with a sheet outline (see [irregular stock](irregular-stock.md)) gets manual cut-offs
only: the planner refuses it ("Automatic cut-offs need a rectangular sheet"), and a batch with
such a plate is blocked like any invalid plate. A manual cut-off on it is cut only where its
line crosses material: each crossing is a segment of its own that starts at the material's edge
and overtravels past the far one, trimmed around parts as usual and within the user's limits.
The head-locked overcut applies only to a span that reaches the bounding box's far edge.

## Head-locked overcut at the far edge

A cut-off starts only where an edge is certain. The origin-side edge always is. Stock often arrives up to 1.5 in wider than nominal, so the far edge (the one away from the plate's origin, by quadrant) may still have material past it. Without a head-height lock a cut-off never starts at the far edge, and Plan Cutting never reverses one.

**Lock head height and overcut the far edge by** in the automatic cut-off dialog (also opened from Plan Cutting's cut-off settings) turns on a head-locked overcut for cut-offs created afterwards: automatic, Plan Cutting's staged cut-offs, and the manual **Sheet Cut-Off** tool. The choice and amount (1.5 in, or 38.1 mm in a metric nest, by default) are kept between sessions. Existing cut-offs keep theirs; delete and re-add one to change it. Each cut-off stores its own overcut (`CutOff.HeadLockOvercut`), so loading a nest regenerates it exactly.

Only the segment that reaches the far edge is affected, and only when no limit stops the line short of it. The overcut replaces **Overtravel** there.

- Cut toward the far edge (the default): rapid to the segment's start, cut to the nominal far edge, lock the head height, cut on past the edge by the overcut, unlock.
- Started at the far edge (`CutOff.FarEdgeFirst`): rapid to the nominal far edge (for a 48-in sheet that is really 48.5 in, the 48-in mark), lock, cut outward past the edge by the overcut, rapid back to the nominal edge with the head still locked, unlock, cut toward the origin.

Plan Cutting may cut a head-locked far-edge segment either way: the joint search, the safest-route fallback and segment placement each try the nearer end first and keep whichever passes the checks (the safest route takes the one breaking fewer). The plan summary reports how many far-edge segments change direction. Apply installs the segment's program and records the direction on its cut-off, so regenerating, saving and loading keep it. A plan made without confirmed cutting parameters only reorders and never reverses. A direction changed after planning makes the plan stale.

The program marks the locked stretch with `HEAD HEIGHT LOCK` and `HEAD HEIGHT UNLOCK` comments (`HeadHeightLock`). Posts write their configured lock and unlock codes there and refuse a nest with a head-locked cut-off when the codes are not set; see [Cincinnati CL](cincinnati-post-output.md#head-locked-cut-off-overcuts) and [CI Fiber](cincinnati-ci-fiber-post-output.md). The overcut leg lies outside the nominal sheet; the clamp-contact check includes it. Machine behavior with the head locked (piercing at the nominal edge, beam off and rapid back) is unconfirmed: verify on the machine before production.

## Part sequencing

For **Plate > Sequence Parts > Manual Sequence**, choose the one-based sequence number and hover a part on the sheet; only the part under the pointer is outlined. Click it to place it at that exact position, then the number advances up to the last part. Clicking empty sheet space changes nothing. Use **Done**, the window close button, right-click on the sheet, or Escape to leave the tool. Manual reordering changes neither geometry nor quantities.

For **Plate > Sequence Parts > Sequence by Path**, drag lines over the sheet with the left button in the order you want the parts cut; clicking a part adds it as a one-point line that claims the parts whose bounding boxes hold the click. Lifting the button between lines is a rapid: the dashed jump to the next line's numbered start claims no parts. Each part belongs to the line crossing its bounding box that passes closest to its bounding-box center, and lines are cut in drawing order, each in the order its nearest points fall along it; where a line passes a part more than once, the closest pass decides. Parts no line crosses are cut after all the others, in the order they would follow their nearest line, and are drawn muted until a line or click reaches them. The numbers update as you drag, and the plate is reordered when you release. **Undo Line**, Backspace or Ctrl+Z removes the last line; **Clear** or right-click removes them all and restores the order the tool started with. Cut-first parts stay ahead of the rest, and cutoffs follow the same dependency rules as Part Sequencing below. Escape mid-drag drops only that line; otherwise Escape, **Done** or closing the window leaves the tool.

After adding cutoffs, apply **Part Sequencing** to the current plate or all plates. Each trimmed segment of a cutoff is a part of its own in the sequence, and each is moved earlier as needed so it is cut before every part its nominal line passes through within the segment's span: the stretch of the line from the end of the segment before it to the start of the one after it (or the line's start or end). The parts a line passes through lie in the gaps between its segments, so each is cut after the segment on either side of it and no other; the segment below a row of parts is cut with that row, not before a row the line passes through farther on. Segments due before the same part keep the order they were regenerated in. Ordinary parts retain their relative order from the chosen sequencing route. A cutoff that splits the whole sheet — one continuous cut from sheet edge to sheet edge, such as a tail separator — goes after every part and every other cutoff, so the head never travels back across the separated edge. Cutoffs that cross no part but leave gaps keep their normal route position. Cutoff geometry, clearance, part programs, placements, and quantities are unchanged.

The dependency check uses the nominal horizontal/vertical line within the segment's span, not the trimmed cutting segment itself, which intentionally skips the parts (`CutOffSegments` measures the spans from the segment parts). It conservatively checks placed part bounds (including edge contacts), so a cutoff through a concave recess can also move ahead of that part. Definitions are matched by drawing identity, not their displayed names. A cutoff part with no matching definition is conservatively ordered before all ordinary parts, and a segment part whose cut cannot be measured stands for the whole line.

Drawings marked **Cut first** in the drawing editor (for example test squares) are sequenced ahead of every other part: their parts get their own route with the chosen method, then the remaining parts follow on theirs. A cutoff that crosses a cut-first part is still cut before it.

This rule runs when applying automatic sequencing, after reversing the exit-first sequencer route into cutting order. Manual sequence edits are still manual; adding or moving cutoffs does not automatically reapply this rule. Reapply Part Sequencing after layout changes and review the resulting rapids before posting. Regeneration and saving/reloading retain the applied mixed sequence.

The all-plates command uses `PlateSequencing.ApplyAll`, which snapshots the target plate references before sequencing. Reordering parts raises collection events that can replace the nest's trailing empty plate; those events must not invalidate the batch's iteration or skip any original plate. This snapshot is not a transaction or a concurrency guard: sequencing still runs synchronously on the owning thread, using the same per-plate cutoff rules.

## Rerunning, editing, and saving

The command is one-shot; spacing, minimum-strip and minimum-tail inputs start at their defaults each time the dialog opens. Generated lines are ordinary cutoffs and can subsequently be dragged, deleted, or sequenced with the existing tools; Manual Sequence places each segment on its own. Moving parts regenerates their trimmed segments but does not reposition the saved cut-off lines or recalculate the retained tail automatically. Each regenerated segment goes back to the place in the sequence of the saved segment of its cut-off that it overlaps most along the line; a segment with no saved counterpart (a part dropped onto a segment splits it) follows the segment before it, and a cut-off with no saved segments is added at the end. Parts and other cut-offs keep their places relative to it however many segments it now has, so new cut-off settings (fewer or more segments) never push a later part or a sheet separator out of order.

Rerunning unchanged suppresses equivalent existing full-span lines. A limited cutoff at a proposed line is a conflict requiring manual review, not permission to replace it or add overlapping NC moves. Existing definitions are never silently deleted or expanded.

In the plate view, a left-to-right selection window selects a cut-off only when it encloses every visible cut segment; a right-to-left window selects it when it crosses any visible segment (not an empty gap). Cut-offs and parts can be selected together and deleted together. Clicking a cut-off still starts its existing single-line drag.

Saving `.nest` retains ordinary cutoff positions, axes, limits, head-locked overcut and far-edge direction, and the sequence place of every segment (see [the file format](nest-file-format.md#cut-offs)). Loading regenerates cutoff programs using the reader's default cutoff settings; exact toolpaths made with nondefault cutoff settings are not guaranteed to round-trip, and a cut-off that regenerates into a different number of segments loads them together at its first saved place, with every other part and cut-off kept where it was relative to them. Older files that recorded only a cut-off's first place give no segment count, so a sheet separator from one of them is loaded last. Review regenerated paths before posting.

## Trim and extend

**Sheet Cut-Off** stops a new line at the first crossing cut-off from its start edge: the origin side, or the far edge when the cut direction is `TowardOrigin`, in any plate quadrant. Clicking past that crossing still draws the line from the start edge, as the preview shows. The line runs full length when nothing crosses it or what remains would be shorter than the minimum segment length. Tab switches to full-length lines and back, and the choice lasts until the nest is closed. Only the new line's limits are set (`CutOffTrim.StopAtFirstCrossing`); existing lines are not changed. A head-locked line stopped short of the far edge loses its overcut, and the status bar says so.

**Plate > Trim/Extend Cut-Off** (and the toolbar button beside **Sheet Cut-Off**) edits a cut-off against the cut-offs that cross it, AutoCAD-style. Tab switches between Trim and Extend; Esc finishes. Both change only the cut-off's start and end limits (`CutOffTrim` in Core), so nothing new is saved and Plan Cutting sees the change like any other limit change.

- **Trim**: click the piece to remove. The crossing cut-offs on either side of the click (or the line's end) bound the piece, and the limit on that side moves to the crossing line's centre, where half the crossing cut's kerf still overlaps the trimmed end. A crossing line counts when its own span reaches the target, including a line that stops on it.
- **Extend**: click near the end to grow. The end runs to the next crossing cut-off beyond it, skipping one sitting at the current end (click again to go one more step), or to the sheet edge, which clears the limit so the usual overtravel or head-locked overcut applies again.
- **Swap Through-Cut**: right-click where two cut-offs meet, one running through and the other stopping at it. The stopped one extends past the junction as Extend does, and the through one is trimmed there, losing the side away from the plate's origin, since only the origin-side edge is certain. On a 96 x 48 sheet whose verticals stop at a full-length horizontal separator, swapping at the last vertical leaves that vertical splitting the sheet and keeps the area beyond it whole.

The hover preview dashes the piece a trim removes in red and the piece an extend adds in green. Each edit undoes as one step ("Trim Cut-Off", "Extend Cut-Off", "Swap Through-Cut"), regenerates the plate's cut-offs and places the changed cut-offs' segments with `PlateSequencing.PlaceCutOffs`, so a line that now splits the sheet is cut last and one that no longer does moves before the parts it crosses.

The status bar refuses, changing nothing: a cut-off nothing crosses (delete it instead), the middle piece between two crossings (a cut-off has one start and one end), a trim or swap that would leave the line shorter than **Minimum segment length**, an end that already runs to the sheet edge, and a swap where both lines run through or both stop. Trimming the far-edge end of a head-locked cut-off turns its overcut off, and extending back to that edge turns it on; the status bar says which. Clamps do not block an extension: the pre-post clamp check reports it as for any manual cut. On an outlined sheet the edits work the same way, and the line is still cut only where it crosses material.

## Implementation boundary

`AutomaticCutOffPlanner` in Core builds detached definitions and diagnostics without changing the input plate. `AutomaticCutOffOptions.MinimumTailLength` is a finite, nonnegative distance in model units; its programmatic default of zero preserves the previous behavior, while the desktop explicitly supplies its unit-aware 12-in / 304.8-mm default. `KeepHorizontalRemnant` defaults to false; both desktop entry points set it. The plan reports `HorizontalSeparatorY` and `HorizontalRemnantWidth`. `AutomaticCutOffBatch.Create` plans an ordered plate list, and `Apply` replans the complete list before mutating any plate, refusing a blocked batch and recovering touched cutoff state on exceptions. Callers must prevent concurrent edits throughout planning/apply. The desktop dialog renders the active plate's detached preview through `PlateView.SetActiveParts`; both menu commands apply through the shared batch service, which adds definitions to `Plate.CutOffs` and uses `Plate.RegenerateCutOffs`. It must not accept preview parts directly, because doing so would bypass cutoff persistence and regeneration. `RegenerateCutOffs` materializes one part per trimmed segment of each definition (`CutOff.SegmentPrograms`), each with its own place in `Plate.Parts`; `CutOffSegments.Of` finds a definition's segment parts and the span of the nominal line each stands for. Posts emit each segment part like any other part. There are no new nesting rules; the `.nest` format records each segment's sequence place.
